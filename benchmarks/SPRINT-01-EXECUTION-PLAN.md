# Sprint 01 Execution Plan: Frozen Parity Corpus and Real Harness

## Objective

Replace the current declarative benchmark scaffold with a fail-closed,
evidence-producing harness for the frozen Docker CLI/Engine `28.3.2` target.

Sprint 01 does not claim complete parity. It establishes the machine-readable
truth needed to implement and measure parity in S2-S4.

## Start State

Initial benchmark scaffold was YAML-valid but could not be trusted as an
executable corpus:

- scenario tags do not satisfy the declared taxonomy;
- several commands and fixture paths are generic or not evidence-backed;
- `kubernetes` and `elasticsearch` tag-object hashes were recorded instead of
  their peeled commit IDs;
- runner, scripts, reporter, and workflow are not yet one executable system.

## Frozen Target

| Contract | Value | Evidence required |
|---|---|---|
| Docker CLI/Engine | `28.3.2` | exact `docker version --format` output in artifact |
| Docker Engine API | discovered from pinned engine | exact API version artifact; no inferred value |
| Lightr | source commit under test | `lightr --version` artifact |
| Linux execution | GitHub-hosted Ubuntu | workflow run URL and raw JSONL digest |
| macOS execution | named Intel host | owner-run artifact; never substituted by Linux CI |

CI uses `ubuntu-24.04`, never mutable `ubuntu-latest`. It provisions Docker
through a version-pinned mechanism, then asserts both client and server equal
`28.3.2`; mismatch is a hard failure. Provisioner revision/package identity,
full `docker version` JSON, and Engine API version are raw artifacts. Printing
a version without asserting it is not a pin.

## Canonical Scenario Schema

S1-A owns migration. Every scenario gets these fields before it can enter an
execution chunk:

```yaml
id: lower-hyphenated-id
category: build|buildkit|run|compose|network|volume|security|resources|logging|registry|health|plugin|swarm
availability: supported|unsupported|hardware_gated|out_of_scope
reason: required unless availability is supported
fixture:
  project: project-id
  path: relative/path
  context: relative/path
docker:
  command: exact argv or shell command
lightr:
  command: exact argv or shell command
metrics: [at-least-four-defined-metrics]
tags: [at-least-two-taxonomy-values]
assertions:
  - kind: exit_code
    expected: 0
  - kind: stdout_regex
    pattern: '^expected output$'
```

Rules:

- `supported`: fixture and both commands are present; runner executes both.
- `unsupported`, `hardware_gated`, `out_of_scope`: runner emits a typed skip
  with reason. It is never counted as a Docker/Lightr pass.
- `out_of_scope` is allowed only for explicit owner policy: plugin ecosystem in
  S1. Swarm is not out-of-scope after owner decision; it enters S4.
- A scenario has no generic `Dockerfile`, fabricated image name, or shell
  fallback with `||`.
- Corpus conservation is mandatory: exactly 250 distinct scenario IDs and
  `supported + unsupported + hardware_gated + out_of_scope = 250`. No omitted
  or unclassified scenario is allowed.

## Wave Schedule

### Wave A: Truth Freeze — parallel 2

| WP | Owner | Files | Deliverable |
|---|---|---|---|
| S1-A | Lead/agent | `benchmark-spec.yaml`, `parity/**`, `MANIFEST.md` | Pinned capability corpus, real fixture inventory, status matrix, corrected taxonomy/hashes |
| S1-F | Research agent | `research/docker-plugin-adapter.md` | Plugin adapter feasibility and lifecycle probe only |

S1-A gates:

1. Resolve annotated tags through `refs/tags/<tag>^{}`.
2. Clone each declared repo at peeled commit and validate every declared fixture
   path before corpus write.
3. Extract CLI capability surface from `lightr --help` generated by the source
   binary; do not infer commands from prose.
4. Generate a parity matrix with exact source evidence for every status.
5. Add taxonomy values actually used by scenarios; reject category-name tags
   unless category tags are explicitly declared taxonomy values.
6. Mutation: wrong fixture path and tag hash must each fail corpus validation.
7. Add structured assertions for every `supported` scenario; matching exit code
   alone never establishes parity.

### Wave B: Harness — parallel 3

Starts only after S1-A freezes schema and fixture inventory.

| WP | Owner | Files | Deliverable |
|---|---|---|---|
| S1-B | Runner agent | `runner/**` | Rust runner implements new availability schema, chunking, JSONL, merge, strict validation |
| S1-C | Preparation agent | `scripts/00_*` through `06_*`, `verify_hashes.sh` | Noninteractive portable prep, real clone/extract/build/smoke/chunk scripts |
| S1-D | Reporting agent | `reporter/**`, `scripts/07_*` through `09_*`, `validate_contract.py` | Raw merge, evidence validation, basic actual stats, archive/checksum |

S1-B gates:

- exact source-order chunk partition: each supported scenario selected once;
- `unsupported`/`hardware_gated` produce typed skip; failed supported command
  fails command;
- raw record includes command digest, stdout/stderr digest, exit, timing,
  scenario, tool, round, availability, spec digest, fixture tree digest, source
  commit, Docker client/server/API version, Lightr version/digest, and
  host/kernel identity;
- each command has a per-scenario timeout. Timeout kills its process group,
  writes a complete `timed_out` record, and fails selected supported work;
- unit tests: duplicate ID, malformed spec, chunk partition, failed command,
  duplicate raw tuple;
- mutation: remove duplicate-ID validation -> its test red.

S1-C gates:

- canonical path only: `benchmarks/scripts/`;
- root path derived from script directory;
- Linux path has no `vm_stat`, Lima requirement, interactive `read`, or
  in-session `usermod` dependency;
- `docker info`, `sudo docker`, and actual Lightr binary path are verified;
- fixture absence exits nonzero; never `|| echo not found`;
- mutation: wrong hash and absent fixture -> red.

S1-D gates:

- malformed JSONL, duplicate `(scenario,tool,round)`, absent raw evidence,
  missing round, and failed supported record all fail;
- skipped typed availability is reported separately, never passed;
- CSV, JSON and Markdown use actual raw records;
- p-values, CI and effect sizes say `not_computed` until implemented;
- mutation: remove one round -> validator red.

### Wave C: CI Integration — sequential 1

| WP | Owner | Files | Deliverable |
|---|---|---|---|
| S1-E | CI agent | `.github/workflows/benchmark.yml`, `benchmarks/ci/**` | Static path gate, root Lightr build, runner build/test, smoke chunk, manual full matrix |

S1-E gates:

1. Every referenced workflow/script path exists.
2. CI builds root CLI: `cargo build -p lightr-cli --release`; passes absolute
   produced binary to runner.
3. CI builds standalone runner from `benchmarks/runner/Cargo.toml`.
4. CI uses `sudo docker` or explicit Docker daemon service, never `usermod`.
5. Push/PR runs spec gate, runner tests and one real smoke chunk only.
6. `workflow_dispatch` runs matrix chunks `0..19`, `fail-fast: false`, then a
   merge job. Start `max-parallel: 10`; raise to 20 only after a manual smoke
   proves available account concurrency. Queueing is capacity behavior, never
   a test failure.
7. Mutation: invalid path in a generated workflow path manifest fails static
   gate before job execution.

## Integration Plan

1. Lead creates a dedicated feature branch and commits a reviewed benchmark
   scaffold baseline before agent worktrees are created. Generated `target/`,
   cloned repos, caches and artifacts never enter that commit.
2. Lead cold-reviews S1-A and S1-F; updates contract only from evidence.
3. Lead verifies S1-B/C/D independently, including each mutation probe.
4. Lead integrates source files only. Never include `target/`, cloned repos,
   `work/`, result artifacts, Python caches, or `.techlead/`.
5. S1-E lands after local harness integration and actual smoke passes.
6. Independent cold reviewer assesses final diff with no agent transcript.
7. Conventional commits grouped by WP, PR, CI, human approval, squash merge.
   No force push or amend.

## Sprint 01 Definition of Done

- No generic/executable-looking fake command remains in `supported` scenarios.
- Corpus validator, runner test suite, script tests and smoke evidence are
  green.
- CI can execute a smoke chunk and merge its raw evidence.
- Full suite trigger is available but does not claim results until manually run
  and artifacts validate.
- Docs/status describe only evidence actually produced.

## Manifest Rule

`MANIFEST.sha256` is generated from a sorted allowlist and excludes itself.
`MANIFEST.md` records generation command, artifact identity and detached
manifest digest; it never hashes its own mutable contents.
